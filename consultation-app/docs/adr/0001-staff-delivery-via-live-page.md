# Staff delivery via a live, kept-open page — not push or SMS

Barbers need to see a Client's consultation result as soon as it's submitted. We considered push notifications (requires a service worker, push subscriptions, and either a paid push service or a self-hosted VAPID setup) and SMS via a service like Twilio (reliable, but per-message cost and requires storing each Barber's phone number). We chose a live page each Barber bookmarks to their homescreen, updated in real time via a realtime subscription on the `consultations` table while the page is open. This is the cheapest to build and reuses infrastructure the backend (Supabase) already provides. Trade-off: if a Barber doesn't keep the page open, they won't see the result until they check it — there is no out-of-band alert.
